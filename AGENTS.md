# AGENTS.md

## Layout

- Root has no manifests/scripts; work from `backend/` (Laravel 13 JSON API) or `frontend/` (Flutter). Root `README.md` has setup, run, branch and API conventions.
- `docs/api/`: `auth.md`, `operator.md`, `pelanggan.md`, `pengaturan.md`, `padi-masuk.md`, `penjemuran.md`, `bagi-hasil.md`. Update docs when payload/validation changes.
- Dashboard summary aggregates padi-masuk in one query (`ringkasPadiMasuk`); `stok` is hardcoded `0` and `transaksi` duplicates `padi_masuk.jumlah_transaksi` (both kept for the app contract).
- CI: both workflows run on push/PR to `main` and `develop` (and manually). Backend runs from `backend/` with PHP 8.4 (Composer allows ^8.3), MySQL 8 `huller_abang_test` (root/password), `vendor/bin/pint --test` then `php artisan test`. Frontend runs from `frontend/`: `flutter pub get` → `flutter analyze` → `flutter test`. Run the same locally before pushing; a commit that forgets to `git add` a file passes locally but is caught by CI on a clean checkout.
- Timezone is `Asia/Jakarta` (`APP_TIMEZONE`), not UTC: `before_or_equal:today` validation and `durasi_hari` use local dates.

## Backend

- Setup: `composer setup` (install, copy `.env.example`→`.env`, key, migrate, `npm install --ignore-scripts`, `npm run build`) needs MySQL DB `huller_abang` and seeds nothing. Set `OWNER_PASSWORD` (optional `OWNER_USERNAME=owner`) in `.env` then `php artisan db:seed` for owner + default `kelas_padi`/`pengaturan`; owner is skipped when the password is empty.
- Dev: `composer dev` = `php artisan dev`. For Flutter/emulator use `php artisan serve --host=0.0.0.0 --port=8000`; Vite is `npm run dev`/`npm run build`.
- Verify: `vendor/bin/pint --test` then `php artisan test` (exact CI test command); local `composer test` adds `config:clear`. Focused: `php artisan test --filter=...` or `php artisan test tests/Feature/FooTest.php`. Feature tests require a running MySQL `huller_abang_test`; `phpunit.xml` fixes connection/db, host/user/password come from `.env` locally and CI env in workflows; no SQLite fallback. Unit tests need no DB.

### API conventions

- `ApiResponse::sukses()` always emits `{success,message,data}` (data may be null); `gagal()` omits `data` and adds `errors` only for 422. 422 errors are `{field,message}`; 401/404/405 renderers are registered in `bootstrap/app.php` via `ApiExceptions::daftarkan()` and gated to `api/*`.
- Routes: public `/health` (checks DB) and `/login` (`throttle:login`: 5/min per username+IP, 20/min per IP, 429 JSON with `Retry-After`); `/logout` needs only `auth:sanctum`; everything else uses `['auth:sanctum','aktif']` (`PastikanAkunAktif` → 401 for deactivated accounts): `/me`, dashboard, `POST /bagi-hasil`, `GET/POST /pelanggan` (operators may add petani/pengepul only, never `milik_huller`; `pelanggan.dibuat_oleh` records the creator), read-only pengaturan/kelas-padi, and padi-masuk/penjemuran. Owner-only (`role:owner`): operators and all other pelanggan/pengaturan/kelas-padi routes, including `GET /pelanggan/{id}/riwayat-transaksi`. `role` middleware returns 403 via `ApiResponse::gagal`. Framework health is `/up`.
- Duplicate pelanggan (same `nama` case-insensitive + same non-empty `kontak`, among non-deleted) is rejected with 422 on `nama`.
- Pagination `page`/`limit` (max 100) → `data.items` + `data.meta`; exceptions: `/kelas-padi` returns all + `meta.total`, `/penjemuran` has a plain array in `data`, `/pengaturan`, `/me`, dashboard are single objects. Pelanggan/operator silently clamp `limit`; padi-masuk and riwayat-transaksi reject `limit>100` with 422.
- State guards return 409: edit padi only while `masuk`, penjemuran mulai needs `masuk`, selesai needs `dijemur`, selesai-giling needs `siap_giling`; void fails only when already `void`. There is no `DELETE /padi-masuk/{id}`; use `POST /padi-masuk/{id}/void` with trimmed `alasan` 3–500 chars.

### Padi masuk / penjemuran

- FormRequests: `PadiMasukRequest` (tanggal `Y-m-d`, pelanggan_id existing non-deleted, kelas_padi_id exists, berat_basah_kg numeric>0 ≤99999999.99 with ≤2 decimals, catatan trimmed nullable ≤1000); riwayat filters `search`/`pelanggan_id`/`kelas_padi_id`/`status`/`tanggal_dari`/`tanggal_sampai`; customer history uses the same minus pelanggan/kelas. `MulaiPenjemuranRequest.tanggal_mulai` is optional: if supplied it must be ≥ padi tanggal, otherwise the service uses today. `SelesaiPenjemuranRequest` requires `berat_kering_kg` ≤ `berat_basah_kg` and `tanggal_selesai` ≥ tanggal_mulai; `BagiHasilRequest` requires berat>0 and two 0–100 percentages with ≤2 decimals.
- State/calcs in `App\Services\PadiMasukService`: lowercase `masuk` → `dijemur` → `siap_giling` (constants on `PadiMasuk`); the DB column is `status_transaksi`, not `status`. `durasi_hari = max(0, diff)`; `persen_susut = round((berat_basah-berat_kering)/berat_basah*100, 2)`. Duration < `AMBANG_DURASI_HARI` (2) triggers a warning; `BATAS_DURASI_TERLALU_LAMA` is 3 and feeds `penjemuran.durasi_terlalu_lama`. Ongoing duration is computed up to today while DB `durasi_hari` stays NULL until finish. `selesaikanGiling` also sets `tanggal_selesai_giling`; `batalkan` sets `void_reason`/`void_by`. `nomor_transaksi` (`PM-YYYYMMDD-XXXX`) is generated on create via `PadiMasuk::creating`/`App\Support\NomorTransaksi`, is immutable on edit, and is exposed by `format()`.
- Two response families: nested `format()` shape under `/api/padi-masuk/...`; flat Flutter list under `/api/penjemuran/...` (`id,pelanggan,kelas,tanggal_masuk,berat_basah,tanggal_mulai/selesai,berat_kering,persen_susut,durasi_hari,terlalu_lama,status`). Penjemuran must last at least `PadiMasukService::MIN_JEMUR_HARI` (2) days: `tanggal_selesai` earlier than `tanggal_mulai + 2` is rejected with 422 on `tanggal_selesai` (checked before "not in the future" in `PenjemuranController::selesai`, with a `DomainException` → 409 backstop in the service and on `PUT` corrections), and the flat row carries `boleh_diselesaikan` + `tanggal_paling_cepat_selesai` so the app disables "Selesaikan" (`minHariJemur` in `penjemuran_model.dart`). `durasi_hari`/`terlalu_lama` are computed by the server (`PadiMasukService::durasiJemurHari`, Asia/Jakarta); the app only falls back to local math for older servers. `GET /padi-masuk` `meta` also carries `jumlah_aktif` and `total_berat_kg` for the whole filtered result (void excluded) so the app summary stays correct while data loads page by page.
- Audit `log_padi_masuk` via `tulisLog()` on create/update/start/finish/giling/void; no-op updates are not logged. Actions: `dibuat`, `diubah`, `penjemuran_dimulai`, `penjemuran_selesai`, `selesai_giling`, `void`. `GET /padi-masuk/{id}/log` is paginated newest-first.

### Schema / auth

- `users` have no email; login uses unique `username`, with `role` enum `owner|operator`, `aktif`, and soft deletes (a hard delete would violate the `dibuat_oleh`/`void_by`/`user_id` foreign keys; a soft-deleted username stays reserved). Deactivating an operator, changing their password, or deleting them revokes all their tokens; `aktif` is also enforced per request by the `aktif` middleware. Tokens expire after `SANCTUM_EXPIRATION` minutes (default 10080 = 7 days; `sanctum:prune-expired` is scheduled daily). Logout revokes only the current token. `User` casts password hashed; `OperatorController` also calls `Hash::make` (not double-hashed).
- Indonesian/unprefixed tables: `users`, `pelanggan` (soft deletes), `pengaturan`, `kelas_padi`, `padi_masuk`, `penjemuran`, `log_padi_masuk`, `log_pengaturan`. `PUT /pengaturan` logs old/new percentages before updating; each field is independently optional (`required_without`) and numeric 0–100.
- Bagi hasil: `upah = beras * persen_upah/100`, `operator = upah * persen_hak_operator/100`, `huller = upah - operator`, `saldo = beras - upah`; each step rounds to 2 decimals.
- `GET /pelanggan/{id}/riwayat-transaksi` returns `pelanggan`, `terakhir`, `items`, `meta`; `status_terakhir` comes from the latest non-void transaction regardless of filters.

## Frontend

- Verify: `flutter pub get`, `flutter analyze`, `flutter test`; focused `flutter test test/riwayat_transaksi_test.dart`. Tests: `widget_test.dart` (login, pelanggan model/validator, settings parsers, bagi-hasil math), `padi_masuk_test.dart`, `riwayat_transaksi_test.dart`, `tampilan_test.dart` (small-screen renders; no Penjemuran/HomeShell), `api_client_test.dart` and `controller_test.dart` (HTTP faked with `MockClient`: assign `Sesi.instance.api.klien` or pass `ApiClient(klien: ...)`). Widget tests that do not fake HTTP rely on failed API calls for error/empty states.
- API base is compile-time `API_URL` in `lib/core/api_client.dart`: `--dart-define=API_URL=http://<host>:8000/api`, default `http://10.0.2.2:8000/api`; backend must bind `0.0.0.0`. For a USB phone against a localhost backend use `adb reverse tcp:8000 tcp:8000` with `API_URL=http://localhost:8000/api`. Cleartext HTTP is allowed only in `src/debug` and `src/profile` manifests; the main manifest declares `INTERNET` and release builds require an HTTPS `API_URL`.
- Auth/session: `Sesi.instance` singleton, token in SharedPreferences key `token`, restored via `GET /me`; login/logout call `/login`/`/logout`. `ApiClient` clears the token on 401 and flattens backend `errors` to field→message; a 401 on a request that carried a token calls `onSesiBerakhir`, so `Sesi` signs the user out and the login page shows "Sesi Anda telah berakhir" once (`ambilPesanSesi`). A failed login (401 without token) is not a session expiry. `Sesi.instance.owner` only composes tabs in `lib/home_shell.dart` (owner 6 tabs; operator Padi Masuk + Penjemuran); it is not a route guard — backend roles enforce access. Phones show the first 3 owner tabs plus "Lainnya"; width ≥840 uses a NavigationRail.
- Data/pages: pelanggan and operator load every page via `ApiClient.getSemuaHalaman` (client-side search/type filtering needs the full list); padi-masuk riwayat loads 100 per page with a "Muat lebih banyak" button (`PadiMasukController.muatLagi`), and its header uses the server `meta` totals. Padi masuk form/riwayat live in `features/penggilingan/`; the form loads read-only pelanggan/pengaturan/kelas-padi (operator-accessible). `PelangganCard` opens `features/pelanggan/pages/detail_pelanggan_page.dart` (edit/delete + history); history uses `RiwayatTransaksiController` and `/pelanggan/{id}/riwayat-transaksi?limit=100`, with `pelanggan.status_terakhir` driving summary text.
- Void uses `core/konfirmasi_void.dart` + `POST /padi-masuk/{id}/void` (never DELETE); void cards hide print/share actions. Bagi-hasil preview uses `POST /bagi-hasil` with local `BagiHasil.hitung` fallback; saving percentages uses `core/konfirmasi_pengaturan.dart`; padi cards print via `features/penggilingan/struk_padi_masuk.dart` (`pdf` + `printing`); share uses `core/share_pdf.dart` (Web Share API on web, `Printing.sharePdf` native sheet/download fallback).
- Contract notes: padi-masuk riwayat filters are `dari`/`sampai` (what the app sends); `GET /pelanggan/{id}/riwayat-transaksi` uses `tanggal_dari`/`tanggal_sampai`. `PenjemuranService` goes through `ApiClient` (shared token, 401 handling, field-level error messages) and sends `berat_kering`. Frontend validator drift: berat ≤1000000 vs larger backend limit; the penjemuran page's `pelanggan_id` filter list is never populated.
- Keep formatting churn out of diffs: do not run `dart format lib` over the whole tree (older files are not formatted); format only the files you changed.
